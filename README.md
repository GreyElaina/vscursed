# VSCursed

> 该 README 由人类编写。  
> 鉴于生成式人工智能技术在文档方面惊人的能力低下，这被认为是必要的。

把 Cordis 接入 VSCode 内部，一种更不稳定，更强大一些，更适合偏执狂的 VSCode 扩展构建方案。  
你不觉得这种做法[似曾相识](https://en.wikipedia.org/wiki/Minecraft_modding)吗？是的，巧合的是，他们现在都是 Microsoft。但显然，我采取的这种方法不会得到那样的发展。  
比起那样创造性的壮举在世界各地开花结果，这只是一个偏执狂的妄想，不会掀起多大的风浪。它会在一阵烟尘滚滚中被忘记，直到有另一个人再次尝试并失败。
但在那之前，还有尚能从中得到的一些东西。

基于一套稳定小巧的运行时内核，在通过针对特定版本的 VSCode，准确来说，是 VSCodium 的基础上的一套 Patch，我们成功的注入并能够访问到 VSCode 的内部基础设施。在生成式人工智能的帮助下，这套 Patch 可以快速地沿上有发行版本进行迭代，而不会造成成本过高或过于迟滞等问题。  
何况 VSCodium 的发行节奏相对来说已经较 VSCode 自身慢上许多，这可以提供一个足够稳健的工程实施前提。

由于这是一个个人项目，考虑到工程实施方面的困难，我也将在该仓库中维护我自己使用的插件。其他人也可以将其视作某种参照，尽管这会对仓库结构以及可能的其他直接围绕 VSCursed 进行开发的人们造成影响，但我觉得 monorepo 比维护个什么 sdk 好多了，反正这里也有 submodule 来提供构建系统。
